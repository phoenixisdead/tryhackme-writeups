## Description
This write-up documents the investigation performed in the TryHackMe "Investigating with Splunk" room. The analysis focuses on identifying attacker activity through Splunk logs, including malicious user creation, registry modification, encoded PowerShell execution, and external network communication.

Investigating with Splunk – TryHackMe Write-up

Overview

In this room, we investigate suspicious activity using Splunk logs stored in the main index. The objective is to analyze Windows and Sysmon logs to identify attacker activity such as user creation, registry modifications, PowerShell execution, and malicious network communication.

---

Total Events Collected

To determine the total number of logs ingested in the environment, the following search was used:

index=main

This returned 12,256 events in the main index.

---

Identifying the Backdoor User

User account creation events in Windows are logged under Event ID 4720.

Search used:

index=main EventID=4720

Reviewing the event details showed a newly created account. In the event log, the username A1berto appeared under:

- New Account
- Account Name
- SAM Account Name

This indicates that the attacker created a new user account named A1berto.

---

Registry Modification

After creating the user account, the attacker also modified a registry key related to the new user.

Registry modifications are logged by Sysmon under Event ID 13.

Search used:

index=main EventID=13 A1berto

The registry path was visible in the TargetObject field:

HKLM\SAM\SAM\Domains\Account\Users\Names\A1berto

This confirms the system registry was updated when the new account was created.

---

User Impersonation

Next, we investigated which legitimate user the attacker attempted to impersonate.

Search used:

index=main EventID=1

Event ID 1 logs process creation events.

Looking at the User field values revealed several accounts, including:

cybertees\Alberto

From this information we can determine that the attacker attempted to impersonate the legitimate user Alberto.

---

Command Used to Create the Backdoor User

Process creation logs also revealed the exact command used by the attacker.

Search used:

index=main EventID=1 | table User CommandLine

This exposed the command used to create the backdoor user remotely:

C:\windows\System32\Wbem\WMIC.exe /node:WORKSTATION6 process call create "net user /add A1berto paw0rd1"

This command uses WMIC to remotely execute a process that adds a new user account.

---

Login Attempts from the Backdoor User

To determine whether the backdoor account attempted to log in, we examined Windows logon events.

Windows logon attempts are recorded under Event ID 4624.

Search used:

index=main EventID=4624 A1berto

No results were returned from this search, indicating that the A1berto account did not attempt to log in.

Total login attempts observed: 0

---

Infected Host Running PowerShell

Next, we searched for PowerShell activity related to the attacker.

Search used:

index=main powershell A1berto

Reviewing the results showed that the suspicious PowerShell commands were executed on the host:

James.Browne

---

Malicious PowerShell Execution Events

To determine how many events were generated by the malicious PowerShell activity, we searched for PowerShell logs.

Search used:

index=main powershell

In the UserID field, two Security Identifier (SID) values appeared:

Example format:

S-1-5-21-XXXXXXXXXX

These are Windows Security Identifiers, which uniquely identify user accounts.

One SID had 79 events, while another had 19 events. The malicious PowerShell execution corresponded to the SID with 79 logged events.

---

Encoded PowerShell Web Request

The attacker executed an encoded PowerShell command that contacted an external server.

The encoded string was extracted and decoded using CyberChef.

After decoding from Base64 using the Decode Text (UTF-16) recipe, the script revealed:

$ser=$([Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('aAB0AHQAcAA6AC8ALwAxADAALgAxADAALgAxADAALgA1AA==')));$t='/news.php';

The Base64 string was decoded again to reveal the server address:

http://10.10.10.5

The script then appended the path:

/news.php

Final URL:

hxxp://10[.]10[.]10[.]5/news[.]php

The URL was defanged to prevent accidental access, again by using cyberchef.

---

Conclusion

Using Splunk, we were able to trace the attacker’s actions within the compromised environment. The attacker created a backdoor user account, modified registry entries, attempted to impersonate a legitimate user, and executed encoded PowerShell commands that communicated with an external server.

By analyzing Windows and Sysmon logs, we successfully reconstructed the attacker’s activity and identified the malicious behavior within the system.
